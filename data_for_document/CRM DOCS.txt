RM Document Repository & HTML Document Generator

## 1. Project Overview

Develop a dedicated section within the existing CRM system that functions as a centralized **Document Repository and HTML Document Generator**.

The purpose of this module is to allow authorized CRM users (agents) to select predefined HTML document templates, populate them with client information and additional custom data, preview the completed documents, and export them in different formats.

Each document template will consist of HTML code containing predefined placeholders that can be dynamically populated with CRM data and manually entered information.

## 2. User Authentication & Access

- The module must be accessible only to authenticated users.
- Users must log in using their existing CRM username and password.
- Access permissions should follow the CRM's existing user roles and authorization structure.

## 3. Document Repository

Admin Creates a dedicated section within the CRM called **Document Repository**.

### Required functionality:

- Display a list of all available document templates.
- Each document should have a title/name and, optionally, a description.
- Documents should be stored as HTML templates.
- Clicking on a document should open the document editor interface.
- The system should support multiple document templates.
- The architecture should allow new templates to be added, edited, or removed without requiring changes to the core application.

## 4. Document Editor – Interface Layout

Once a document is selected, the system should display a two-panel interface.

**Left Panel – Input & Configuration**

Contains all fields and controls used to populate the selected document.

**Right Panel – Live Document Preview**

Displays a real-time preview of the HTML document, reflecting all changes made in the input panel.

The preview should automatically update whenever an input value changes.

## 5. Client Information Integration

The first option in the left panel should allow the agent to associate the document with an existing client in the CRM.

### Client selection:

- Provide a searchable dropdown or client search field.
- Allow the agent to search for a client by name, email, phone number, or CRM client ID.
- Once a client is selected, automatically retrieve the relevant information from the CRM database.

### Automatically populated client information:

- Full Name
- Email Address
- Residential / Business Address
- Phone Number

The retrieved information must automatically populate the corresponding placeholders within the HTML document.

### Important:

- The system must use dynamic placeholders rather than hardcoded client information.
- If a client record is updated, the agent should be able to refresh the client information in the document.
- Agents should also be able to manually edit populated fields where permitted.

## 6. Custom Input Fields

In addition to the CRM client information, each document template should support custom input fields.

These fields will be defined according to the requirements of each individual document template.

### Supported input types:

- Text fields
- Numeric fields
- Date fields (optional)
- Multiline text fields (optional)

Examples of custom fields:

- Reference Number
- Transaction Amount
- Investment Amount
- Payment Date
- Case Number
- Additional Comments
- Custom Notes

### Requirements:

- Each HTML template should define which custom fields are required.
- The system should automatically generate the relevant input fields based on the selected template.
- Input values must be dynamically inserted into the HTML document.
- Changes must be reflected immediately in the live preview.
- Required fields should be validated before allowing document export.

## 7. HTML Template & Placeholder System

Each document must be based on an editable HTML template.

The HTML templates should support dynamic placeholders for both CRM client information and manually entered data.

Example:

`{{client_name}}`

`{{client_email}}`

`{{client_address}}`

`{{client_phone}}`

`{{reference_number}}`

`{{transaction_amount}}`

`{{payment_date}}`

The system should replace these placeholders with the corresponding values when generating the final document.

### Template requirements:

- HTML and CSS should be supported.
- Each template should maintain its own design and formatting.
- Templates should support professional document layouts, including headers, footers, tables, logos, and signatures.
- Missing or empty values should be handled gracefully.
- Dynamic content must be safely escaped to prevent HTML or JavaScript injection.
- The generated document should preserve the original template formatting.

## 8. Document Preview

The right panel should display a live preview of the generated document.

### Required functionality:

- Automatically refresh the preview when a client is selected.
- Automatically refresh when CRM information is populated.
- Automatically refresh when an agent changes any input field.
- Preserve HTML formatting, fonts, spacing, tables, and images.
- Provide a preview that closely matches the final exported document.

The preview should be isolated from the CRM application to prevent template HTML or scripts from affecting the main CRM interface.

## 9. Document Export & Output Options

Once the document has been populated, the agent should have three output options.

### Option A – Download HTML

- Generate the completed HTML document.
- Allow the agent to download it as an `.html` file.
- The downloaded file must contain the populated information and necessary styling.

### Option B – Copy HTML Code

- Provide a button to copy the complete generated HTML source code.
- The copied code should include the document's HTML structure and styling.

### Option C – Print / Export as PDF

- Provide a Print / Export PDF button.
- Generate a print-ready version of the completed document.
- Allow the agent to save or print the document as a PDF.
- Ensure page breaks, margins, headers, footers, and formatting are handled correctly.

## 10. Suggested User Workflow

1. Agent logs into the CRM using their credentials.
2. Agent navigates to the Document Repository.
3. Agent selects a document template from the available list.
4. The document editor opens in a two-panel layout.
5. Agent searches for and selects an existing CRM client.
6. The system automatically retrieves the client's information.
7. The relevant client information is inserted into the HTML template.
8. Agent completes the additional custom input fields.
9. The live preview updates automatically.
10. Agent reviews the completed document.
11. Agent selects one of the available output options:
   - Download HTML
   - Copy HTML Code
   - Print / Export PDF

## 11. Technical & Functional Considerations

- The module should integrate with the existing CRM database and authentication system.
- HTML templates should be stored centrally and managed independently.
- Each template should have its own field configuration.
- The placeholder replacement engine should support dynamic data binding.
- The preview should update without requiring a page reload.
- The system should support multiple agents working simultaneously.
- All generated documents should preserve their intended formatting.
- Sensitive client information must be protected through appropriate access controls.
- The system should not execute untrusted JavaScript contained in uploaded or stored templates.

## 12. Suggested Future Enhancements

The architecture should ideally allow the following features to be added later:

- Document template management interface (Create / Edit / Delete).
- Ability to upload or paste HTML code directly into a new template.
- Document generation history.
- Saving completed documents against the relevant CRM client profile.
- Agent activity logs showing who generated each document and when.
- Support for additional export formats such as DOCX.
- Digital signature integration.
- Document version management.

## 13. Expected Deliverable

A fully functional CRM module consisting of:

1. Secure access through existing CRM authentication.
2. Centralized HTML Document Repository.
3. Document selection and editing interface.
4. Automatic CRM client data integration.
5. Dynamic custom input fields per template.
6. Real-time HTML document preview.
7. HTML download functionality.
8. Copy HTML source functionality.
9. PDF printing/export functionality.

**Primary Objective:** Create a flexible document-generation system inside the CRM that allows agents to generate professional, personalized documents using predefined HTML templates, CRM client data, and additional manually entered information, without requiring any HTML coding knowledge from the agent.
